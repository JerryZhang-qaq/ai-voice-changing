# 大批训练素材处理性能 · 0.0.4

## 瓶颈证据

用户 RTX 5080 Laptop GPU 的旧流程记录中，约 238 秒歌曲的人声提取含启动约 152 秒，主唱/和声分离约 138 秒；单个模型加载约 3 秒。主要开销是模型推理。按这一个样本外推，15 首相同长度歌曲仅上述两步约 72 分钟，不能视为整批实测。

0.0.3 对四类模型均使用 FP32、窗口 256、重叠 8，每次调用重新启动解释器和加载模型。固定上游 RoFormer 循环未使用 batch_size，单纯增大该参数不能减少推理。上游注意力配置仅计算能力 8.0 分支启用 Flash Attention；其他架构默认禁止该后端。该结论来自源码与构造器，未在用户 GPU 上执行 profiler。

## 已实现

全部歌曲先去伴奏、切片、逐片审核，取消强制整曲和声分离及整曲弃用。可选和声辅助检查只处理未被硬规则排除的切片，默认关闭；去混响和降噪按需运行。训练仅输出所需声部，转换保留可下载的伴奏和和声。

| 模式 | 精度 | 窗口 | 人声 / 和声 / 降噪重叠 | 去混响重叠 | 注意力策略 |
| --- | --- | ---: | ---: | ---: | --- |
| 保真 | FP32 | 256 | 8 | 8 | 沿用旧策略 |
| 均衡（默认） | AMP | 256 | 4 | 2 | PyTorch SDPA 自动选择支持的后端 |
| 快速 | AMP | 256 | 2 | 2 | PyTorch SDPA 自动选择支持的后端 |

AMP 保留 FP32 权重，推理上下文自动转换精度。有限采样在归一化和写出前检查，避免 NaN/Inf 被 PCM 导出掩盖。已知半精度/后端错误或非有限输出回退 FP32，显存不足尝试缩小窗口，最多一次重试；记录实际参数和原因，未知错误正常报告失败。允许融合后端是策略，不能等同于已测得实际选中的内核。

批量 GPU 步骤按模型调度，复用解释器和当前权重；切换前释放上一模型，不要求四份权重同时驻留。切片和声检查使用同一会话。监督沿用原生 Windows Job 与 Linux 进程组，取消、超时及 worker 退出管理后代进程。

模型文件状态未改变时复用摘要和引擎探测；变化后重新检查。来源、用途、权重/配置摘要、参数、精度和策略版本纳入缓存。默认优先复用旧保真人声，避免处理整曲重跑；可以关闭该选项。升级保留所有数据和缓存。

整批步骤与当前模型分块分别计数，显示原曲名、第几首、切片位置和实际执行参数。整批进度不因重试降低，输出和损伤检查预留步骤尾部。阶段估时依据已完成、未命中缓存的音频秒数与耗时推算剩余音频，首次观测前保持未知。不声称这是完整任务的确定完成时间。

## 已执行对照与局限

实际固定 unwa 权重、同一中文带伴奏 8 秒输入、窗口 256、CPU FP32 和旧注意力策略，仅对照重叠 8 / 4 / 2。推理为 124.328 / 71.323 / 47.060 秒；首次加载 9.710 秒，后两次复用权重。全部输出有限、352800 帧 / 44100 Hz，后两份相对基准 RMS 差值比为 0.0000359 / 0.0000643。[完整报告](benchmarks/0.0.4-separation-report.json)。

该样本不足以证明自然复杂和声、弱声或高音的整体音质；未测 CUDA AMP、Flash Attention、峰值显存或用户 15 首整批耗时。回退、参数与缓存身份、模型复用、进程取消和计数有自动化回归。浏览器流程对 GPU 核心使用明确的 CPU 替身，另行执行真实音频分析和审核。

## 本机复测与后续工作

包内 benchmark 脚本在分离环境中以同一输入比较保真、均衡和快速，保留各输出供 A/B 试听，记录推理 / 加载 / 总用时、实际精度、回退及峰值显存。指令见 [Windows 指南](windows.md)。正式验收需复测弱声、气声、高音、长音、句尾、自然和声及噪声混响，并记录 15 首整批各阶段用时、复核片段变化与训练后听感。

以下尚未实现：有界 CPU 并发队列与 GPU 工作重叠、批量任务暂停/恢复、目标有效人声时长处理、保守活动区间跳过、自动选材及编译加速。现有步骤缓存可在重新提交时复用，不等同于暂停恢复。活动区间优化须保留辅音、气声和尾音的上下文与采样点映射，通过整曲对照后再启用。
